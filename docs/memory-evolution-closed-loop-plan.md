# 记忆 × 自进化：让两条真实闭环转动起来

> **日期**: 2026-08-15
> **背景**: M4 True RSI 受限递归收官后，对项目的深度复盘沉淀。
> **一句话结论**: LAAP-AGI 区别于传统量化框架的差异化能力是**记忆**与**自进化**，二者能力骨架均已具备；但都缺"真实交易决策反馈"这层养分。下一步最值钱的事不是再加任何能力，而是给记忆和自进化各接一条真实闭环。

---

## 1. 项目评价沉淀（为什么是记忆 + 自进化）

传统量化工具（vn.py / Backtrader / 聚宽）是**无状态的计算器**：回测跑完就忘，策略之间不对话，参数靠人肉调。LAAP-AGI 试图让系统"记住市场"和"改进自己"——这是 LLM 时代量化 agent 才有的差异点。

- **记忆**：跨 session 的状态保持 + 复盘闭环。价值在三层递进——
  1. 还记得昨天对这个标的的判断（可检索的事实）；
  2. 能把一次亏损交易的教训喂回下次决策（可复用的经验）；
  3. 记忆不只是存档，而是**参与推理**（注入决策 prompt 的权重）。
- **自进化**：策略迭代自动化。但要警惕传统框架没有的致命陷阱——**过拟合的自我强化**。一个能改自己代码/参数的系统，若没有严格的样本外纪律，会越"优化"越贴合历史、对市场突变毫无抵抗力。因此"默认关闭、人工授权、可回滚"不是保守，是必要的自我约束。

**现状快照**：记忆系统能力已齐备（`UnifiedMemory.encode_experience / retrieve_context / generate_memory_prompt / consolidate`，且 `memorize_market`、`memorize_kline_daily` 等已在吃真实行情）；自进化 M1-M4 全链路完成但默认关闭（`LAAP_EVO_ENABLED` / `LAAP_TRSI_ENABLED`）。二者都缺**真实决策反馈**：`paper_signals=0`、orders 是 seed，意味着没有真实交易结果可以沉淀成经验、也没有真实业绩可以驱动进化。

---

## 2. 现状诊断

| 维度 | 记忆 | 自进化 |
|---|---|---|
| 能力骨架 | ✅ UnifiedMemory 全接口（经验/概念/技能/工作记忆/检索/整合） | ✅ M1-M4（硬沙箱/调度/治理/受限递归） |
| 数据来源 | ✅ 行情/自选股/K线（memorize_* 在跑） | ⚠️ fitness = 测试通过率/延迟/记忆召回，**与交易业绩脱节** |
| 决策反馈 | ❌ paper trade 的**决策理由/结果/教训**未结构化沉淀 | ❌ 无样本外回测验证，进化目标不指向业绩 |
| 参与决策 | ❌ 下单/信号生成时未注入相关历史经验 | ⚠️ 默认关闭，未接入真实交易循环 |

**诊断结论**：两条能力都停在"有骨架、没闭环"——记忆在存档但没参与推理，自进化在待命但没有交易目标。

---

## 3. 闭环 A：Paper Trade 决策 → 经验记忆 → 参与推理

**目标**：让每笔 paper trade 的决策理由、结果、教训自动沉淀成**可检索、可参与推理**的记忆。

### 3.1 决策留痕（信号/订单落库时）

paper signal/order 写入时，附加结构化 `decision_record`：

```json
{
  "trade_id": "pt_20260815_001",
  "symbol": "600519",
  "action": "buy",
  "ts": 1786800000,
  "rationale": "放量突破 20 日均线，MACD 金叉，机构净流入",
  "basis_memories": ["recall://20260814/600519/pattern", "recall://2026/lesson/追高"],
  "risk_note": "大盘情绪偏弱，仓位 ≤ 5%",
  "expected": "5 日内 +3%"
}
```

实现位置：paper trade 后端落库点（`paper_signals` / `paper_orders` 写入处）增加决策理由字段。

### 3.2 结果回填（平仓 / 复盘时）

订单平仓或复盘时，回填 `outcome` 并生成 `lesson`：

```json
{
  "outcome": {"pnl_pct": -2.1, "hold_days": 3, "vs_expected": "missed"},
  "lesson": "追高突破在情绪弱市失败率高；突破需配合量能确认",
  "lesson_type": "overbought_chase",
  "verified": false
}
```

### 3.3 经验沉淀（教训校验 → 写入记忆）

`outcome` + `lesson` 经过简单校验后调用 `UnifiedMemory.encode_experience(...)` 写入，`lesson_type` 作为检索键。**校验原则**：教训必须来自 ≥1 次真实平仓结果，未验证的 lesson 标记 `verified: false`，防止单笔噪声污染记忆（记忆污染是闭环 A 的头号风险）。

### 3.4 参与推理（信号生成 / 下单前注入）

信号生成或下单决策时，用 `UnifiedMemory.retrieve_context(...)` / `generate_memory_prompt(...)` 注入相关历史经验：

- 同标的近期决策与结果；
- 同 `lesson_type` 的历史教训（如"追高"、"抄底过早"）；
- 当前市场状态的相似 episode（`get_recent_episodes` / `get_related_concepts`）。

注入后，模型输出 `rationale` 必须引用/回应这些记忆（`basis_memories` 字段），形成"记忆 → 决策 → 结果 → 新记忆"的闭环。

### 3.5 验收标准

1. 连续 N 笔 paper trade 平仓后，`encode_experience` 写入 ≥ N 条经验记忆（含 outcome + lesson）；
2. 新决策时 `retrieve_context` 能检索到同标的/同 lesson_type 的相关经验，且注入 prompt；
3. 复盘视图可沿 `trade_id → decision_record → outcome → lesson` 完整追溯；
4. 记忆查询含 `verified` 标记，未验证教训不参与推理（或仅作弱信号）。

## 4. 闭环 B：样本外回测上的受限自动调参（人工审批）

**目标**：让自进化指向**交易业绩**，且在样本外纪律下受限运行、人工审批落地。

### 4.1 交易适应度（fitness 换血）

`FitnessEvaluator` 当前权重：测试通过率 0.4 / 延迟 0.3 / 记忆召回 0.3——这是"软件健康度"，不是"交易业绩"。为进化增加**交易适应度分量**：

```
trade_fitness = 样本外回测综合分
   = w1 * 累计收益 + w2 * 夏普(Sharpe) + w3 * (1 - 最大回撤)
```

建议交易适应度与软件健康度并存：进化只接受"软件健康度不降 + 交易适应度提升"的变更（双门槛）。

### 4.2 样本外纪律（过拟合的第一道闸）

每次进化评估必须做数据切分：`train / validation / out-of-sample(OOS)`。

- 只允许在 train/validation 上迭代；
- **只接受 OOS 上不劣化的改进**；
- OOS 切分按时间（而非随机），防止未来函数泄漏；
- 记录每次进化评估的 OOS 结果到 `state/evolution_audit.jsonl`，可追溯。

### 4.3 受限自动调参（先参数级，代码级保持受限）

- 复用参数级 RSI（`RSIMetaEngine`，已有 `/v1/rsi/...` API + rationale 留痕）；
- 自动产出调参提案 → 沙箱回测评估（交易适应度 + OOS 纪律）→ `awaiting_approval`；
- 走 M3 授权 API（`/v1/evo/deploy` 语义或等价人工审批）落地，失败可回滚（SafeRollback）；
- **代码级受限递归（M4 `true_rsi.py`）保持默认关闭**——先跑通参数级闭环，代码级留作后续在治理完备前提下的扩展。

### 4.4 验收标准

1. 一次受限自动调参完整走通：提案 → 沙箱回测（train/valid/OOS 切分）→ OOS 不劣化 → 人工批准 → 落地 → 审计记录；
2. 落地后可回滚，回滚后软件健康度测试（现有 379 项）不回归；
3. 交易适应度进入 `state/evolution_audit.jsonl`，可跨进程追溯；
4. 未满足 OOS 纪律的提案被自动拒绝（fail-closed）。

---

## 5. 实施顺序与工作量

两条闭环**可并行**，但建议先后关系：**A 是 B 的数据前提**——B 的交易适应度需要真实回测/交易结果，而真实结果需要决策留痕（A 的产物）。因此：

| 阶段 | 内容 | 预计 | 交付 |
|---|---|---|---|
| A-1 | paper trade 决策留痕 + 结果回填 + 教训沉淀（3.1-3.3） | 0.5-1 人日 | decision_record / lesson 字段 + 落库 |
| A-2 | 记忆参与推理（3.4） | 1 人日 | 信号/下单前注入 + rationale 引用 |
| B-1 | 交易适应度 + OOS 切分纪律（4.1-4.2） | 1 人日 | trade_fitness + OOS 门禁 |
| B-2 | 受限自动调参 + 人工审批接线（4.3） | 1 人日 | 调参闭环跑通 + 审计 |
| 收尾 | 验收标准逐条核验 + 回归（379/0 不降） | 0.5 人日 | 验收报告 |

总计约 **4 人日**，零新认知模块、零新框架——全部复用现有记忆系统与 M1-M4 进化基础设施。

---

## 6. 风险与原则

| 风险 | 说明 | 对策 |
|---|---|---|
| **过拟合自我强化**（闭环 B 头号风险） | 自进化越优化越贴合历史，对市场突变无抵抗力 | OOS 时间切分 + 只接受 OOS 不劣化 + 人工审批 |
| **记忆污染**（闭环 A 头号风险） | 单笔噪声/错误教训固化，污染后续决策 | `verified` 标记 + 多笔校验 + consolidate 周期清理 |
| **进化目标错位** | fitness 指向软件健康度而非交易业绩 | 交易适应度与软件健康度双门槛 |
| **治理失效** | 自动落地失控 | 沿用 M1-M4 治理：人工授权、审计、回滚、默认关闭 |
| **信号链路未通** | `paper_signals=0`、orders 是 seed，闭环无真实数据可吃 | 先打通真实信号/订单数据源，闭环才不是空转 |

> **根本原则**：这两条闭环的价值不在"系统看起来能记忆/能进化"，而在**真实交易决策经过记忆与进化后变得更好**。所有验收都以"真实数据 → 真实决策 → 可量化的结果反馈"为准绳。
